# UAV 输电线路巡检系统中文操作说明

## 1. 项目功能

本项目提供成都双图巡检任务生成、起终点重规划、Mission 回放，以及由 8001 编排 8002 视频识别和 8003 缺陷检测的巡检感知流程。系统是研究与演示原型，不直接控制真实无人机。

## 2. 环境安装

主项目建议使用独立 Conda 环境：

```powershell
conda activate uav_planning
python -m pip install -r requirements.txt
```

8002、8003 使用各自项目和环境；不要把其源码或依赖复制进本仓库。真实模型模式还需要服务作者提供的权重与运行环境，最终应在提供模型的电脑上验证。

## 3. 启动三个服务

分别打开三个终端，先启动外部服务，再启动主系统：

```powershell
# 8002 视频识别服务（在其独立项目目录）
conda activate yolo
python -m uvicorn app:app --host 127.0.0.1 --port 8002

# 8003 缺陷检测服务（在其独立项目目录）
conda activate power
$env:PROCESSOR_ARCHITECTURE="AMD64"
python -m uvicorn server:app --host 127.0.0.1 --port 8003

# 8001 主系统（在本仓库根目录）
conda activate uav_planning
python app.py
```

健康检查地址分别为 `http://127.0.0.1:8002/api/v1/health`、`http://127.0.0.1:8003/health` 和 `http://127.0.0.1:8001/debug/ping`。Windows 上的 `PROCESSOR_ARCHITECTURE` 只在当前 PowerShell 会话设置，不修改系统全局环境变量。

## 4. Mock 与真实模型模式

自动化测试使用 HTTP mock，不要求启动 8002/8003。真实模式必须启动两个独立服务并准备兼容视频及模型权重；不要把 mock 通过等同于真实模型已验证。

## 5. 成都双图输入与 Mission

`data/image_datasets.json` 中的 `chengdu_real` profile 显式区分：

- `chengdu_real_line.png`：红线、骨架和拓扑；
- `chengdu_real_point.png`：绿色巡检点检测和证据图。

线路图按 profile 在内存中右裁 2 列并保持左上原点与坐标不变。打开 `http://127.0.0.1:8001`，选择成都数据并点击“生成任务”即可得到 Mission A。IP_0007 会通过真实的 `point_access/free_flight` Mission 段连续访问 raw 点。

## 6. 起终点重规划与回放

在地图输入合法起点、终点并应用重规划可得到 Mission B。重规划保留巡检点身份、访问顺序语义和显式 point access。点击播放后可切换 1x/5x，检查无人机沿 Mission geometry 连续移动且 13 个巡检点各触发一次。

## 7. 巡检感知面板

巡检感知区域包含“目标识别”“处理进度”“识别与缺陷结果”三个 Tab：

1. 从当前 Mission 的权威巡检点列表选择 point ID；
2. 选择本地视频并开始识别；
3. 在处理进度中观察 queued/running/completed；
4. 在结果 Tab 查看关键帧、缺陷类别、置信度和标注图。

前端只访问 8001；标注图片通过 8001 的受控媒体代理加载。

## 8. 感知接口四元组

`mission_id`、`inspection_point_id`、`frame_id`、`timestamp_ms` 必须从视频任务到缺陷结果原样贯穿。`inspection_point_id` 只能来自当前 Mission 的 `inspection_points[].point_id`；`frame_id` 是不可改写的字符串，`timestamp_ms` 是非负视频相对毫秒数。

## 10. 常见错误

- 端口占用：确认 8001/8002/8003 未被其他进程使用。
- 感知服务不可用：先分别访问两个 health 接口。
- 巡检点被拒绝：重新生成/加载当前 Mission，禁止手工补零或改写 ID。
- 标注图打不开：检查 8003 输出是否存在及 8001 media proxy 响应。
- Windows CPU 架构异常：仅在 8003 启动终端设置 `PROCESSOR_ARCHITECTURE=AMD64`。

## 11. 已知限制

当前 A→B→C 连续重规划仍从磁盘 Mission A 读取 baseline；封版演示仅保证初始 Mission A 到单次起终点 Replan Mission B。进程内 Mission registry 和感知 Job Store 在服务重启后不会保留。
